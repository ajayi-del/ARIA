## 2. P0 — Money-Integrity Bugs (verified personally)

### C1 — Basket TP1 harvest double-books PnL and abandons the live remainder
`main.py:8923-8958` + `main.py:6109`.
The harvest closes `_close_size = size × _eff_harvest` (a fraction), but on success calls `_record_close(sym, pos, pnl, mark, "basket_tp1")` with **`pnl` = full-position unrealized PnL**, and `_record_close` → `position_manager.close(sym, 0, ...)` **pops the entire position**. The (1−f) remainder stays open on SoDEX with no software stop (guardian iterates `position_manager._positions`), no time-stop, native TPs already cancelled by basket mode (`main.py:8561`). The in-code comment — "Remainder runs to individual TP2/TP3" — is false. Consequences: unprotected live exposure; the remainder later re-added as "untracked" and closed a second time → **double-booked PnL, corrupted hist_wr, poisoned calibration**.

### C2 — Dust purge fakes a successful close without sending an order
`main.py:6496-6503`. When `size × mark < $10`, `_close_with_retry` returns `OrderResult(order_id="dust_purge", status="filled")` — **no exchange order is sent**. Callers (time-stop 8081, software-TP 7726, stop-dust 6599) then `_record_close`: PnL booked, tracking dropped. The sub-$10 position remains open, and reconciliation permanently skips re-adding it (`reconciliation_dust_skipped`, 7334-7336). Orphaned, unprotected, can bleed or liquidate invisibly. Booked PnL is fictional.

### C3 — Emergency time-stops record the close before the order is sent
`main.py:7936-7940` and `7958-7962`. `asyncio.create_task(_close_with_retry(...))` — **unreferenced, GC-collectable, result never inspected** — immediately followed by `_record_close(...)`. If the close rejects or the task is collected, tracking is gone, PnL booked at mark, no retry, live unprotected position.

### H1 — Resting brackets never cancelled on software closes → stop stacking, instant dumps on re-entry
Time-stop (8070-8084), software-TP (7717-7730), stop guardian, profit cap (8441), flip guard (2905) all close **without one `cancel_order` call**. Native stop/TP orders are GTC reduce-only — they survive. Re-entry of the same symbol (explicitly re-enabled at 8967) inherits stale triggers at old prices; a stale TP below mark can instantly dump the new position. Startup sync places a fresh stop with `old_stop_order_id=None` (968-976) without cancelling the prior session's → **stops stack across restarts**.

### H2 — Auto-adjust partial close has zero bookkeeping
`main.py:2886-2892`: fire-and-forget trim with no `_record_close`, no `pos.size` update. Position manager keeps stale full size → TP1-detection threshold (`exchange_size <= initial × 0.65`, 7384) misfires: a ≥35% auto-adj trim is indistinguishable from a TP1 fill → **golden stop + TP2/TP3 cancellation + trailing mode on a position that never hit TP1**.

### H3 — Fees and funding are never deducted; "net" PnL is gross
`execution/funding_tracker.py` has **zero call sites** (verified). `_record_close` journals `pnl_usd` and `trade_journal.py:239` defaults `pnl_net_usd = pnl_usd`. Every downstream learner — calibrator windowed WR, Nietzsche conviction `(hist_wr − 0.50)`, symbol-edge — trains on numbers inflated by taker fees ×2 + funding. On a $155 account, fees are a large fraction of edge. **This alone can flip a losing system's perceived WR above 50%.**

### H4 — TP-ladder quantization can over-allocate or strand dust
`execution/sodex_client.py:1833-1841`: sub-step legs are bumped *up* to `step`, which can push `sum(tp_qtys) > size`; the correction loop reduces only ONE leg then `break`s. Reduce-only caps per fill, so early TPs cannibalize size reserved for later TPs → tail position left with no TP → dust → the C2 path.

### Phase 2 — Close the loops

4. **Bypass registry:** every bypass declared in config with precondition, expiry, and mutual-exclusion. Campaign gets a balance precondition.
